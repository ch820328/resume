**題目：描述一次你主持重要會議的經驗。**

**回答：**
主持高效會議的關鍵在於 **「會前對齊、會中控場、會後追蹤」**。

在推動 **Engineering Hub (統一開發門戶)** 的初期，我主持了一場關鍵的技術協調會。當時參與的有各個不同工具的維護者，大家對「統一門戶」這件事充滿了疑慮，擔心自己的權限被限縮或工作量增加。

我是這樣主持這場會議的：
1.  **會前設定預期**：我提前發送了議程與一個 **「3 分鐘 Demo」**。我不讓大家在會上才開始思考，而是讓大家先看到「統一門戶能帶來的視覺化好處」。
2.  **會中「拉回焦點」**：會議進行到一半時，兩位同事開始爭執「後端應該用 Python 還是 Node.js」。我立刻介入：「技術選型固然重要，但今天我們的核心目標是 **『使用者路徑的整合』**。技術細節我們線下再開一個小組討論，現在我們先聚焦在介面規範上。」
3.  **確保每個 Action 有主人**：會議結束前 5 分鐘，我總結了三個關鍵決定，並明確了負責人與 Deadline。

**結果：**
那次會議原本預計兩小時，最後在 50 分鐘內就達成了關鍵共識。同事們反饋說，這是我參加過最「不痛苦」的協調會。對我來說，主持會議的成功在於 **「把大家最寶貴的時間花在最重要的決策上」**。
