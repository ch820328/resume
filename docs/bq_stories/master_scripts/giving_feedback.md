**題目：你如何給予他人建設性的回饋 (Feedback)？**

**回答：**
我給予回饋的原則是 **「對事不對人，且一定要附帶可執行的解決建議」**。

有一次在 Code Review 時，我發現一位同事的腳本雖然功能正確，但代碼結構非常鬆散，且完全沒有考慮到「異常處理 (Exception Handling)」。如果就這樣進站，未來維修的人會非常痛苦。

我是這樣給予回饋的：
1.  **肯定現有的成果**：我先留言：「這部分邏輯處理得很清晰，成功解決了 X 的功能需求。」
2.  **明確指出風險而非錯誤**：我沒有說「你寫錯了」，而是寫道：「在現有的網路環境下，如果不加入 Try-Except 機制，當遠端連線超時，整個自動化流水線可能會卡死，導致我們需要人工重啟。」
3.  **提供具體參考範例**：我不只叫他改，我直接附上了一段我之前在 **RFTool** 裡寫過的標準錯誤處理範本給他參考。我對他說：「這是我之前踩過的坑，你可以參考這段寫法，會穩固很多。」

**結果：**
他非常感激我的提醒，並迅速進行了重構。後來他甚至主動把這段錯誤處理邏輯封裝成了一個通用模組。這次經驗讓我學到，好的回饋不應該讓對方感到受挫，而是要讓對方覺得 **「你是在幫他規避未來的風險」**。
