**涵蓋題目：**
*   處理難搞成員/隊友的經驗？
*   如何與不配合的人合作？

**回答：**
我處理「難搞」成員的原則是 **「不將對方的行為視為人身攻擊，而是視為一種待解決的『技術阻塞』」**。

在推動 **RFTool 框架** 時，團隊中有一位資深同仁非常不配合。他習慣原本的快寫腳本，對我推動的物件導向框架充滿敵意，常在會議中冷嘲熱諷，私下也拒絕將他的腳本遷移到新框架上，這導致我們的代碼庫出現嚴重的斷層。

我採取了以下行動：
1.  **私下對齊動機 (Motivation Alignment)**：我沒有在會議上與他爭論。我找他 1-on-1，我發現他反對並非因為懶惰，而是他非常自豪於腳本的「執行效率」，他擔心 OO 框架會產生過多封裝開銷。
2.  **賦予實質影響力 (Empowerment)**：我告訴他：「你是團隊裡最懂效能的人，我希望邀請你擔任框架的『效能審核員』。只要你覺得我的 Base Class 封裝太重，你就直接要求我重寫。」
3.  **建立共同成功**：當他感覺自己不是被「強迫接受工具」，而是被「邀請優化架構」時，他的態度發生了 180 度的轉變。

**結果：**
他不僅不再阻礙進度，反而幫我優化了框架的底層邏輯，讓 RFTool 的效能提升了 15%。這次經驗讓我體會到，所謂「難搞的人」通常只是 **「才華放錯了地方」**。作為 L4，我的任務是幫他們找到那個能發揮價值的支點。
