**題目：如果在會議上同事把不完全是你的錯怪到你頭上，你會如何反應？**

**回答：**
老實說，在會議上被當眾指責時，第一秒的感覺一定是 **「很不爽」**，特別是當我知道問題出在上游、而對方連查都沒查就直接噴我時。但我強迫自己先「深呼吸」，因為我知道在憤怒下回嘴只會讓場面變得很難看，對解決問題也沒幫助。

當時在 **BIOS Guardian Tool** 的緊急會議上，那位同事當著大家的面說：「這都是因為你的工具太爛、不穩定，才卡住進度。」我當下的反應是：**「先救火，事後再釐清 (Fix the problem, deal with the person later)。」**

我沒有跟他爭辯，直接回他：**「現在在這裡噴我也沒辦法讓工具動起來。給我 30 分鐘，我先去把問題修掉，晚點我們再來細談到底是哪裡壞了。」** 這句話成功把大家的專注力從「找戰犯」拉回「解決問題」。

修完 Bug 後，我沒有去跟主管告狀，而是帶著分析數據直接去找那位同事。我把 Log 指給他看，證明是因為上游 BIOS 介面改動才壞的，並非工具本身的代碼錯誤。我直白地對他說：**「兄弟，下次在會上開砲前，先跟我對一下資訊，不然這樣大家都尷尬。」**

**結果**：
他後來私下向我道了歉，我們甚至因為這次「說開了」而變成了更有默契的夥伴。後來我還主動搞了一個內部回歸測試流水線，就是為了讓大家（包括他）以後不用再猜到底是誰的錯，讓數據直接說話。這次經驗讓我體會到，處理不公平指責最好的方式，是 **「用效率贏得尊重，用事實解決衝突」**。
