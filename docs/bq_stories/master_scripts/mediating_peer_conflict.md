**題目：你曾經調解過兩位同事之間的衝突嗎？結果為何？**

**回答：**
我處理同儕衝突的原則是 **「過濾情緒雜訊，將人際衝突轉化為技術規格的定義 (Filter emotions, focus on specs)」**。

曾有兩位資深工程師在協作一個模組整合時產生了嚴重衝突。他們私下都不斷向我抱怨對方的「配合度極差」，導致開發進度完全停擺。

我採取了以下行動：
1.  **分頭釐清想法 (Individual Deep-dive)**：我先分別與兩人進行 1-on-1。我發現所謂的「態度問題」，本質上是 **「技術假設的落差」**。其中一人認為應該使用靈活的 JSON 格式，另一人則堅持要用高效能的 Binary 格式。因為兩人都沒有把這個「假設」說破，只是一直在代碼中互相覆蓋對方的改動，才導致了情緒爆發。
2.  **移除情緒並聚焦重點 (De-escalation & Focus)**：我將兩人拉在一起開會，並設定了一個規則：「今天的會議不准討論個人的感覺，我們只討論 **『數據結構與效能需求』**。」我引導他們把各自擔心的風險（靈活性 vs. 延遲）列在白板上。
3.  **達成共識的介面格式**：在釐清了彼此的技術顧慮後，我協助他們定義出了一套 **「雙方都能接受的介面格式 (Standard Interface Format)」**。

**結果**：
當技術上的「猜測」被明確的「規格」取代後，他們之間的人際摩擦也隨之消失了，專案最終順利合併。這次經驗讓我體會到，團隊中許多人際衝突其實都是 **「資訊不對稱」** 造成的。身為調解者，最重要的任務就是 **「找出那層沒說破的技術隔閡」**，用專業解決衝突。
