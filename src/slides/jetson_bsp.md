# Jetson Build Service & Automation Portal

### 💬 口語講稿 (Pitch Script)
「在開發 Jetson 專案時，我們發現非專家級的團隊成員（例如 QA 或是硬體工程師）經常在編譯映像檔時卡關。Jetson 的 CLI 參數非常複雜，而且建置過程高度依賴本地端的環境設定。為了解決這個痛點，**我和另一位資深工程師合作，從零到有打造了一個 Web-based Build Portal**。我們實作了一個視覺化的步驟選擇介面，並在後端導入 Docker 來徹底隔離執行環境。這樣一來，使用者只需要在網頁上點擊他們需要的設定，就能自動產出客製化的 OTA 或 MassFlash 映像檔。這個專案不僅達成了 **100% 的建置可重現性**，還徹底消除了手動設定環境的冗長工時，把複雜的基礎建設問題轉化成了好用的內部產品。」

### ❓ 面試必殺題預覽
- **Q: 為什麼選擇做 Web Portal 而不是只寫個 Script？**
  *A: Script 仍然需要使用者具備一定的 CLI 操作能力，而且難以提供直覺的「步驟選擇」功能。Web Portal 把複雜度隱藏在後端，讓 QA 甚至硬體團隊能以 self-service 的方式產出 Image，這體現了良好的 Product Sense，不只是為工程師解決問題，更是為整個產品團隊賦能。*
- **Q: 你們怎麼解決環境不一致的問題？**
  *A: 我們在後端使用了 Docker 容器化技術。每次 Build 都是在乾淨、隔離的環境中執行，確保了無論是誰觸發建置，產出的結果都是 100% 可重現 (Reproducible) 的。*
- **Q: 這個專案中你負責了哪些部分？**
  *A: 這個軟體專案只有我和另一位資深同事負責。我們從需求訪談、Web UI 的步驟選擇設計，到後端 Docker 隔離與 Jetson CLI 的自動化封裝，都是我們共同包辦的。這讓我累積了非常多 Full-stack 開發與基礎設施自動化的實戰經驗。*
