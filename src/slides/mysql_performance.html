MySQL 8.x Optimization & Production Line Reliability

Performance Infrastructure
Challenge: [EN] Our automation service (~5,000 RPM) initially suffered from frequent **SQLite File Lock collisions**. During the subsequent migration to MySQL 8.x, our stress-testing framework proactively identified a critical performance regression in the new version.
[TW] 產線自動化服務（約 5,000 RPM）初期飽受 **SQLite 檔案鎖 (File Lock)** 碰撞之苦。在隨後遷移至 MySQL 8.x 的過程中，壓測框架主動抓出了新版本中的關鍵性能回歸。
Solution: [EN] Built a high-fidelity stress test using **sysbench** to reproduce resource conflicts. Leveraged this framework as a **"Performance Safety Net"** to tune MySQL 8.x's log writer threads and locking logic, resolving both original and version-specific bottlenecks.
[TW] 使用 **sysbench** 建立高仿真壓測框架以重現資源衝突。並將此框架作為 **「性能安全網」**，調優 MySQL 8.x 的日誌線程與鎖邏輯，同時解決原始併發與新版本的性能瓶頸。
Impact: [EN] Eliminated 100% of lock-induced downtime, restoring 24/7 stability to the production line. Recovered write throughput with **30% additional headroom**, establishing a data-driven validation standard for future infrastructure upgrades.
[TW] 徹底消除鎖死導致的停機，恢復產線 24/7 穩定運作。恢復寫入吞吐量並預留了 **30% 的擴展空間**，為未來的基礎設施升級建立了數據驅動的驗證標準。
