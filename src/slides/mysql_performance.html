MySQL 8.x Optimization & Production Line Reliability

Performance Infrastructure
Challenge: [EN] Our automation service (~5,000 RPM) initially suffered from frequent **SQLite File Lock collisions**. During the subsequent migration to MySQL 8.x, our stress-testing framework proactively identified a critical performance regression in the new version.
[TW] 產線自動化服務（約 5,000 RPM）初期飽受 **SQLite 檔案鎖 (File Lock)** 碰撞之苦。在隨後遷移至 MySQL 8.x 的過程中，壓測框架主動抓出了新版本中的關鍵性能回歸。
Solution: [EN] Developed a high-fidelity Technical Validation Framework using sysbench. Beyond basic lock testing, proactively monitored latency metrics to identify a hidden MySQL 8.x performance regression, providing the critical data needed for infrastructure tuning.
[TW] 使用 sysbench 開發了高仿真技術驗證框架。在基礎鎖定測試之外，主動監控延遲指標以識別隱藏的 MySQL 8.x 性能回歸，為基礎設施調優提供關鍵數據支持。
Impact: [EN] Successfully flagged critical performance risks before go-live, enabling a 100% stable migration. Established a Data-Driven Validation Standard for future infrastructure upgrades with 30% performance headroom.
[TW] 在上線前成功預警關鍵性能風險，實現了 100% 穩定的遷移。為未來的基礎設施升級建立了數據驅動的驗證標準，並確保了 30% 的性能餘裕。
