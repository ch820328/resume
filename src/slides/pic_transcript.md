# Deterministic BIOS OCR Engine

### 💬 口語講稿 (Pitch Script)
「當時部門內原本有一套自研的 LLM 模型在做 BIOS 畫面的 OCR 驗證。但當 BIOS 介面發生大幅度改版時，這套模型直接失效了。如果要重新訓練，不僅非常耗時，而且原本模型在做精準比對時，就已經存在一些無法根除的穩定性問題。我重新評估了 ROI，決定放棄『凡事皆 AI』的思維。我改用 OpenCV 實作了一套 **Template Matching (模板匹配) 引擎**。為了克服複雜的 BIOS 佈局，我加入了空間排版分析 (Spatial Layout Analysis) 以及動態列分群邏輯。這個『反璞歸真』的做法不僅避開了龐大的重訓成本，還把辨識準確率推升到 99.9% 以上，且延遲只有幾毫秒。這套系統最後成功取代了脆弱的 AI，達成了 100% 穩定的全自動視覺測試。」

### ❓ 面試必殺題預覽
- **Q: 為什麼不用 Tesseract 這類的現成傳統 OCR？**
  *A: 因為 BIOS 的字體通常是低解析度的點陣字，Tesseract 在這種字體上的辨識率只有大約 85%，而且它無法輕易處理表格與多欄位的「空間排版 (Spatial Context)」關係。*
- **Q: 可以解釋一下什麼是「動態列分群 (Dynamic row-grouping)」邏輯嗎？**
  *A: 當畫面上有很多文字時，我們不能只知道「有這個字」，還必須知道字在哪裡。透過 Y 軸的座標投影與群聚演算法，我把同一行的特徵綁定在一起，讓引擎能理解「這個值是屬於左邊這個欄位名稱的」，確保結構化資料萃取的正確性。*
- **Q: 遇到解析度變更或字體微調時，Template Matching 不就會失效嗎？**
  *A: (您可以補充說明有建立自動化的 Template 產生腳本，或是利用影像縮放 (Scaling) 與金字塔 (Image Pyramid) 技術來增加容錯率，展現您對傳統 CV 的掌握度。)*
