Secure Python Execution in UEFI (Python.efi)

Firmware Security
Challenge: [EN] Distributing automated test scripts across global factory sites posed a significant risk of unauthorized execution and logic tampering. Standard Python interpreters lacked a secure loading mechanism for encrypted assets in the pre-boot environment.
[TW] 全球工廠分發自動化測試腳本時，面臨腳本被未授權執行或篡改的風險。標準 Python 解釋器在 UEFI Pre-boot 環境中缺乏對加密資產的安全加載機制。
Solution: [EN] Developed a **Secure Decryption Pipeline**. Modified the **EDK II Python.efi** C source to integrate an RSA-AES decryption engine. Encrypted scripts are decrypted directly in memory before execution, ensuring the source never touches the disk in plaintext.
[TW] 開發 **安全解密流水線**。修改 **EDK II Python.efi** 源碼，整合 RSA-AES 解密引擎。加密腳本在執行前直接於內存中解密，確保源碼全程不以明文形式落地。
Impact: [EN] Established a **Zero-Trust execution environment** for all firmware validation tools. Prevented unauthorized script usage with millisecond decryption latency, ensuring 100% testing integrity across the global supply chain.
[TW] 為全球供應鏈建立 **零信任執行環境**。以毫秒級的解密延遲，徹底杜絕了測試工具的非法使用，確保 100% 的測試完整性。
